# Resumo — Versionamento com Git e GitHub

O controle de versão registra as alterações de um projeto ao longo do tempo. O Git é um sistema distribuído: mantém um repositório local, permite criar commits com mudanças preparadas e organizar o trabalho em branches. GitHub hospeda repositórios Git e oferece recursos de colaboração, como pull requests e revisão de código.

O fluxo básico que quero lembrar é conferir **git status**, revisar com **git diff**, selecionar arquivos com **git add**, conferir o conteúdo preparado e criar um commit com uma mensagem clara. **git log** ajuda a acompanhar o histórico. Branches separam mudanças; **git merge** integra uma branch à atual.

Para compartilhar, **git push** envia commits ao remoto; **git fetch** baixa as atualizações sem integrá-las; e **git pull** busca e integra mudanças à branch atual. Pull request é um recurso do GitHub para propor, discutir e revisar uma integração.

Versionamento facilita colaboração, rastreabilidade, comparação de versões e recuperação de mudanças. Ele funciona melhor junto com commits pequenos, revisão, comunicação e testes. Consulte as [anotações](./anotacoes.md) para comandos e atividade e a [documentação oficial do Git](https://git-scm.com/docs).
